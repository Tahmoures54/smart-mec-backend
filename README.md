# مکانیک هوشمند — Backend

سرور Next.js برای اپ فلاتر **مکانیک هوشمند**: ورود OTP، عیب‌یابی با هوش مصنوعی، اشتراک طلایی، پرداخت زیبال، رفرال، و جستجوی تعمیرگاه‌های نزدیک.

زنده: [smart-mec.ir](https://smart-mec.ir) — استقرار ایران: [smart-mec.liara.run](https://smart-mec.liara.run)

## استقرار لیارا (اینماد)

برنامه Next.js روی پلتفرم `next` لیارا با `liara.json` تنظیم شده است. متغیرهای `.env.example` را در کنسول لیارا وارد کنید، بعد یکی از این دو:

- کنسول لیارا → استقرار جدید (GitHub یا آپلود)
- یا در GitHub یک Secret به نام `LIARA_API_TOKEN` بگذارید تا workflow `CD-Liara` (`.github/workflows/liara.yaml`) روی `main` دیپلوی کند

دامنه `smart-mec.ir` را در لیارا → دامنه‌ها اضافه کنید. ابر آروان را برای `@` و `www` **خاموش** کنید و رکوردهایی که لیارا می‌دهد (ALIAS/CNAME و TXT) را جایگزین A فعلی Vercel کنید. اینماد دامنه `.liara.run` را قبول نمی‌کند؛ باید روی `smart-mec.ir` باشد.

💳 درگاه پرداخت — زیبال (Zibal)
پروژه از زیبال به‌عنوان درگاه پرداخت استفاده می‌کند.

جریان پرداخت
کاربر محصول را انتخاب می‌کند → POST /api/purchase

سرور یک درخواست به gateway.zibal.ir/v1/request می‌فرستد

زیبال یک trackId برمی‌گرداند و سرور آن را به عنوان authority در دیتابیس ذخیره می‌کند

کاربر به gateway.zibal.ir/start/{trackId} هدایت می‌شود

پس از پرداخت، زیبال کاربر را به /api/purchase/verify?trackId=...&success=1&status=2 برمی‌گرداند

سرور با gateway.zibal.ir/v1/verify تراکنش را تأیید می‌کند

در صورت تأیید (result === 100)، محصول به حساب کاربر اضافه و کمیسیون رفرال پرداخت می‌شود

متغیرهای محیطی
متغیر	توضیح	پیش‌فرض
ZIBAL_MERCHANT	کد مرچنت از پنل زیبال (برای Sandbox: zibal)	—
ZIBAL_REQUEST_URL	اندپوینت ایجاد درخواست پرداخت	https://gateway.zibal.ir/v1/request
ZIBAL_VERIFY_URL	اندپوینت تأیید پرداخت	https://gateway.zibal.ir/v1/verify
ZIBAL_START_URL	اندپوینت هدایت کاربر به درگاه	https://gateway.zibal.ir/start
ZIBAL_TIMEOUT_MS	مهلت پاسخ درگاه (میلی‌ثانیه)	15000
اگر ZIBAL_MERCHANT تنظیم نشده باشد، سرور در حالت MOCK اجرا می‌شود و تراکنش‌های ساختگی برای تست محلی ایجاد می‌کند.

⚠️ نکته واحد پول
قیمت‌های PRODUCTS (در src/types/index.ts) به تومان ذخیره می‌شوند، اما زیبال فقط ریال می‌پذیرد. تبدیل در src/app/api/purchase/route.ts با ثابت TOMAN_TO_RIAL = 10 انجام می‌شود. مبلغ ذخیره‌شده در دیتابیس همواره تومان است تا با MIN_WITHDRAWAL، کمیسیون رفرال و گزارش‌های ادمین سازگار بماند.

امنیت پرداخت
کال‌بک /api/purchase/verify عمداً بدون JWT است تا زیبال بتواند آن را فراخوانی کند.

تکمیل پرداخت فقط با result === 100 از زیبال و تنها در صورتی که تراکنش در دیتابیس pending باشد انجام می‌شود.

به‌روزرسانی تراکنش در یک db.transaction اتمی انجام می‌شود تا از اعطای دوباره محصول جلوگیری شود.

IP سرور را در پنل زیبال → بخش «محدودیت‌های Access Token» ثبت کنید.

تنظیمات پنل زیبال
کد مرچنت را از zibal.ir → بخش API Tokenها دریافت کنید.

IP سرور لیارا را در محدودیت‌های توکن ثبت کنید.

برای تست اولیه، مقدار ZIBAL_MERCHANT=zibal را در محیط staging قرار دهید تا از Sandbox رسمی زیبال استفاده شود.

امنیت عملیاتی
فایل .env را commit نکنید. اگر قبلاً در تاریخچه گیت بوده، secretها را rotate کنید.

UNIVERSAL_BYPASS_CODE فقط برای محیط توسعه؛ در production خالی بگذارید.

کال‌بک زیبال عمداً بدون JWT است؛ تکمیل پرداخت فقط با status=pending و تأیید درگاه انجام می‌شود.

در پنل لیارا و Vercel، متغیر PAYPING_TOKEN (میراث نسخه‌های قبلی) را در صورت وجود حذف کنید.

## 🔄 خلاصه تغییرات نسبت به نسخه قبلی

| خط | قبل | بعد |
|---|---|---|
| **مقدمه** | «پرداخت PayPing» | «پرداخت زیبال» |
| **بخش پرداخت** | نداشت | بخش کامل «درگاه پرداخت — زیبال» با جریان، متغیرها، امنیت |
| **نکته واحد پول** | نداشت | توضیح تومان ↔ ریال |
| **امنیت عملیاتی** | «کال‌بک PayPing عمداً بدون JWT» | «کال‌بک زیبال...» + توصیه حذف `PAYPING_TOKEN` |
| **متغیرهای محیطی** | اشاره‌ای نبود | جدول کامل با مقادیر پیش‌فرض |

## 🎯 چرا این تغییرات مهم‌اند؟

1. **جدول متغیرهای محیطی:** برای هر توسعه‌دهنده جدید یا آینده‌ی خودتان، در یک نگاه مشخص است چه چیزی لازم است.
2. **نکته واحد پول:** اگر این را ننویسید، احتمالاً یک نفر در آینده باگ `* 10` را حذف می‌کند و همه قیمت‌ها ۱۰ برابر می‌شوند.
3. **توصیه حذف `PAYPING_TOKEN`:** برای اینکه اگر روزی کسی ریپو را clone کرد، متغیر قدیمی را نسازد.
4. **بخش «تنظیمات پنل زیبال»:** برای اینکه در زمان استقرار یا تغییر تیم، این مرحله دستی فراموش نشود.
